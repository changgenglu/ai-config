# 工作流程驗證追蹤

> 追蹤批次 1 修改（systematic-debugging、verification-before-completion、receiving-code-review）在真實任務中的表現。
> 累積 5 個具規模任務的驗證資料後，產出優化報告並決定是否進入批次 2。

**目標任務數**：5（具規模任務：涉及 3+ 檔案、需走規劃→實作→審查流程）
**已完成**：0/5
**當前批次**：批次 1（方法論引用）
**批次 2 就緒條件**：5 個任務驗證完成 + 整體品質 ≥ 70 分 + 無重大流程阻塞
**批次 3 就緒條件**：批次 2 完成 + 3 個以上路徑 A 任務驗證 SDD 相容性

## 重大問題即時處理規則

以下情況**不等待 5 個任務累積**，立即修復並記錄：

| 情況 | 行動 |
|------|------|
| 流程阻塞（兩套系統衝突、路徑找不到、狀態解讀錯誤） | 立即修復 + 記錄根因 + 回報使用者 |
| 整體品質 < 70 分（使用者明確不滿或產出品質明顯下降） | 立即分析根因 + 提出優化方案 + 暫停後續驗證 |
| 子代理連續 2 個任務忽略方法論引用（如不遵循 verification gate） | 強化該代理提示詞 + 記錄改善 |

## 批次升級決策表

| 條件 | 行動 |
|------|------|
| 5/5 完成 + 品質 ≥ 70 + 無重大阻塞 | → 產出優化報告 + 提議進入批次 2 |
| 5/5 完成 + 品質 < 70 | → 產出問題分析 + 先修復批次 1 問題再決定 |
| 3/5 完成但已有明確的批次 2 候選改善 | → 向使用者報告中期發現，但不提前升級 |
| 任何時候發現重大流程問題 | → 立即修復 + 記錄 + 回報使用者 |
